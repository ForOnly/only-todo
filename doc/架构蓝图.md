# Tauri + Vue 桌面应用架构蓝图

> 从 **only-todo** 提炼的可复用架构标准。新项目按本蓝图落地，再按业务裁剪；产品细节仍写在各自的 `产品需求.md` / `技术设计.md`。

可视化概览可在 Cursor 中打开本仓库配套 Canvas（会话内生成）。跨项目复用请启用 Cursor Skill：`tauri-vue-desktop-arch`。

---

## 0. 适用与裁剪

| 场景 | 建议 |
|------|------|
| 本地优先桌面工具（Windows 为主） | **整套采用** |
| 单窗口、无托盘 | 保留分层 + IPC 类型生成；去掉 tray / multi-window |
| 无浮层助理 | **不要**复制 float 几何与会话机；仅保留主窗 |
| 需要云端账号 | 在 Service 层加远程客户端；不要把 HTTP 塞进 Command |

**必须复用**：分层、`AppError`、ts-rs 类型桥、文档三角。  
**按需复用**：多窗口、托盘、调度器、FloatHost。

---

## 1. 技术栈（冻结选型）

```
Desktop:   Tauri 2
Backend:   Rust + Tokio
Frontend:  Vue 3 + TypeScript + Vite
DB:        SQLite 3（WAL）
IPC types: ts-rs → src/api/generated/
Toolchain: mise（Node + Rust）
i18n:      vue-i18n（UI）+ 托盘文案在 Rust 侧
Store:     不用 Pinia / Vue Router（除非确有路由需求）
```

---

## 2. 分层（硬约束）

```
Vue UI / composables
        ↓
api/*（invoke 封装）
        ↓
commands（薄：参数反序列化 + 调 Service + 可选广播）
        ↓
services + domain（校验、状态机、业务规则）
        ↓
repository（SQL）
        ↓
infrastructure（database / notification / filesystem / …）
```

规则：

1. **Command 不写业务**；禁止在 command 里堆 SQL。
2. **Repository 不做校验**；校验与状态机在 Service / domain。
3. **前端不直连 SQLite**；一律走 Command。
4. 写成功后需要跨窗同步时，由后端 `broadcast` / `emit`，前端只 refetch。

错误统一：`Result<T, AppError>` → JSON `{ code, message }`。前端用 `utils/error.ts` 映射到 i18n。

## 4. IPC 契约

### 4.1 Commands

- 注册集中在 `lib.rs` `invoke_handler`。
- 命名：`snake_case`；serde `rename_all = "camelCase"`。
- 分组：按域拆 `commands/<domain>.rs`。

### 4.2 Events（多窗时）

前端常量集中在 `src/constants/events.ts`，与 Rust emit 名一致。典型：

| 事件 | 用途 |
|------|------|
| `settings-updated` | 主题/语言等全窗刷新 |
| `<entity>-changed` | 写成功后列表 refetch |
| 导航/托盘快捷 | 打开创建/设置/定位到实体 |

### 4.3 类型生成

```bash
mise run gen-types   # → cargo run --bin export-ts → src/api/generated/
```

Domain 是 TypeScript 契约的**唯一源**；改字段先改 Rust，再生成。

---

## 5. 多窗口模式（可选）

1. `tauri.conf.json` 为每个 WebView 定义 `label`。
2. `main.ts`：`getCurrentWindow().label` → 挂载不同根 SFC（同一 Vite 入口）。
3. **会话权威在 Rust**（Host / Session）；前端只渲染 + 发 intent command。
4. 次要窗权限用独立 `capabilities/*.json`。

单窗项目：只保留 `main` + `App.vue`。

---

## 6. 托盘与生命周期（可选）

- 关闭主窗 → **hide**，不退出。
- 退出只走托盘「退出」。
- 左键托盘：显隐主窗。
- `single-instance`：二次启动聚焦已有实例。
- 托盘文案随 `ui.locale`（Rust `tray_i18n`），不依赖前端。

---

## 7. 数据层

- 路径：`{app_data_dir}/<app-id>/data.db`
- `PRAGMA journal_mode=WAL` + `foreign_keys=ON`
- 迁移版本化、同事务升级
- Settings 用 KV 表即可起步

---

## 8. 前端约定

| 项 | 约定 |
|----|------|
| 状态 | composable refs；无全局 store（除非跨窗共享且确需） |
| 路由 | 默认无 Vue Router；用视图枚举 / 侧栏状态 |
| 主题 | settings → mount 前 `applyAppearance`；听 `settings-updated` |
| 确认框 | 自建 Confirm，禁用 `window.confirm` |
| 桌面壳 | 禁用浏览器右键/拖入默认；自建上下文菜单 |
| 业务注释 | 中文 |

---

## 9. 文档三角 + Cursor 规则

同一任务内同步：

| 文档 | 职责 |
|------|------|
| `doc/产品需求.md` | WHAT — 用户可见行为 |
| `doc/技术设计.md` | HOW — 架构与接口 |
| `doc/项目进度.md` | LOG — 里程碑与变更 |

项目内放置 `.cursor/rules/doc-sync.mdc`（always apply），强制改功能时改文档。

## 11. 反模式（禁止）

- Command 内写 SQL 或复杂分支
- 手改 `api/generated/*` 类型文件
- 前端把业务规则复制一份与 Rust 分叉（状态机以 domain 为准）
- 用浏览器 `confirm` / 默认右键菜单充当桌面交互
- 改功能不改文档三角
- 把 only-todo 的 companion 几何/贴边逻辑无脑拷进无关产品

## 12. 与 only-todo 的映射

| 蓝图概念 | only-todo 落点 |
|----------|----------------|
| 分层 | `src-tauri/src/{commands,domain,services,repository,infrastructure}` |
| 类型桥 | `bin/export_ts.rs` → `src/api/generated/` |
| 多窗 | `main` / `float-chrome` / `float-body` + `FloatHost` |
| 广播 | `broadcast.rs` + `todos-changed` / `float-session-changed` |
| 调度 | `scheduler/` tick=30s |
| 文档 | `doc/产品需求.md` 等；规则 `.cursor/rules/doc-sync.mdc` |

产品专用细节（工作台视图、助理贴边矩阵等）见 [技术设计.md](技术设计.md)，**不属于**本蓝图的强制部分。
