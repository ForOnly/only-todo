## 1. 架构概览

### 1.1 技术栈

```
Desktop Framework: Tauri 2
Backend:           Rust
Frontend:          Vue 3
Database:          SQLite 3（WAL）
Runtime:           Tokio
```

### 1.2 分层结构

```
Frontend (Vue 3)
  ├── MainWindow       v1.0
  ├── FloatingWindow   v1.1
  └── SystemTray       v1.0
        |
Tauri Command
        |
Service Layer（校验 + 状态机）
        |
Repository Layer
        |
SQLite / System API（Notification）
        |
Scheduler（Tokio，tick=30s）
```

### 1.3 Rust 模块

```
src-tauri/src
├── commands        # Tauri 接口
├── domain          # Todo, Reminder, Status, CompanionSession
├── float           # FloatHost / session / persistence / window_ops / geometry / surfaces
├── services        # 业务逻辑
├── repository      # 数据访问
├── infrastructure
│   ├── database          # Database + with_conn/with_tx；migrations.rs 跑版本化 SQL
│   ├── notification
│   └── filesystem        # app_data_dir / data.db / logs
├── scheduler       # 后台提醒
├── appearance      # 进程级 resolve + 全窗 set_theme
├── events          # 审计写入 + list_events 读取
└── errors          # AppError
```

前端类型契约：`cargo run --bin export-ts`（或 `npm run gen:types` / `mise run gen-types`）从 Rust domain 生成 `src/api/generated/`；`src/api/types.ts` 再导出并补充 UI 常量。`src-tauri/bindings/` 是 ts-rs `#[ts(export)]` 的编译期残留，已 gitignore，不是契约目录。
### 1.4 调用流程

```
Frontend → Tauri Command → Service → Repository → SQLite → Result<T, AppError>
```

**主窗 IA**：顶栏跨库搜索 + 新建 + 设置（无品牌字，窗口标题承担）；侧栏（非搜索时）全部/已完成/标签/归档/回收站（`list_workbench_todos`）；扁平列表，无「今天|库」双模式与焦点台三段分组。选中后右侧滑入 Inspector（无选中不占列）。冷启动：`list.default_view` 为 all 或非法/today/doing/overdue/tag → 全部；done/archived/trash → 对应归类。保存默认落点不切换当前页。「全部」含无 due 的 Todo/Doing，超过 pageSize（50）分页属预期。Inspector autosave（切选/Esc 前 flush；`saveStatus`：idle 不展示 / dirty / saving / saved）；`get_todo` 含软删记录供回收站 Inspector，update/transition 仍拒软删。助理预览只读（标题/描述），无 dirty flush。搜索 Enter 走 `list_todos` keyword（Todo/Doing/Done），搜索时隐藏侧栏。新建走 CreateTodoModal（标题优先 + 更多选项；标签页非搜索时预填 `activeTag`）；创建前 flush；成功后露出列表并 `editingId` 开 Inspector（先清搜索再必要时切 all）。列表时间 token 仅在有 `dueDate` 时展示（`formatListTimeToken` → `formatRelativeDue`）；Inspector 时间块为字段级证据（创建/更新/截止/完成），逾期由截止行自然表达不单独成行。

**桌面交互壳**：`installDesktopGuards`（三窗）禁用浏览器右键与文件拖入默认；`AppContextMenu` 提供剪切/复制/粘贴/全选。任务删除与放弃未保存草稿走 `useAppConfirm` / `AppConfirmDialog`（非 `window.confirm`）。`AppModal`：`closeOnBackdrop` 默认 true（确认框）；新建/设置为 false。Esc 由 `useModalEscStack` 只交给最顶层弹窗。表单控件：`AppSelect`、`AppDateTimePicker`（对外值仍为本地 `YYYY-MM-DDTHH:mm` 字符串，经 `date.ts` 与 ISO 互转；时分为两位文本输入）；打开态 Esc 在 capture 阶段 `stopImmediatePropagation`，不连带关父 `AppModal`；外层滚动关闭 Teleport 浮层（浮层自身滚动除外）。宿主见 `AppShellOverlays`。

**主题与语言**：设置只存偏好 `ui.theme`（`system` \| `light` \| `dark`）与 `ui.locale`（`zh-CN` \| `en-US`）。外观权威在宿主：`AppearanceHost` 以 `UiTheme::resolve(preference, os)` 得到进程内一份 `light|dark`，再对每个 `WebviewWindow.set_theme(Some(resolved))`（标题栏、滚动条、引擎 `prefers-color-scheme` 同源）。Windows 的 OS 色读注册表 `AppsUseLightTheme`（隐藏 WebView 的 `theme()` 不可信）；`ThemeChanged` 只作进程级重算信号，不按窗各自解析。CSS 只认 `@media (prefers-color-scheme)`，**不写 `data-theme`**。前端 JS 不上色、不读 `matchMedia` 决定产品主题；`applyAppearance` 只切 vue-i18n。`get_appearance` 只读 `preference`/`resolved`，给 Canvas 等非 CSS，**不是第二条涂色路径**。`settings-updated` 同步语言与其它设置字段，不改 DOM 主题。状态动词按钮前端按 `target` 映射 `$t('statusAction.*')`（忽略后端中文 `label`）。托盘菜单/tooltip 文案随 `ui.locale`（`tray_i18n`；助理项为单一 `float_action`，随显隐在「显示/隐藏助理」间 `set_text`）。

路径别名：`@/` → `src/`（tsconfig paths + Vite resolve.alias）

多窗口：`main.ts` 按 `getCurrentWindow().label` 挂载 `App.vue` / `FloatChromeApp.vue` / `FloatBodyApp.vue`；共用同一 i18n 创建方式。

### 1.7 桌面助理（v1.1）

产品称「助理」；代码与 settings 仍用 `companion.*` / `CompanionSession` 等标识（不改存储键）。

[`tauri.conf.json`](../src-tauri/tauri.conf.json) 定义 `float-chrome` 与 `float-body`（frameless、transparent、alwaysOnTop）。Rust `FloatHost` 为唯一会话；前端只渲染。事件 `float-session-changed`。会话含派生 `chrome: ball | strip | hidden`。任务/提醒写成功另发 `todos-changed`，主窗与助理 refetch。助理面板：快加、勾选完成、单击即时行内只读预览（列表 DTO 标题/描述）、预览双击或顶栏/详情入口 `show_main_window`；列表按 `companion.visible_count`（出厂 10）分页，`total > page` 时底栏「还有 N 条」以**无 todoId** 打开主窗。助理不挂 `useTodoDetail` / 不 dirty flush。主窗监听 `todos-changed`：列表先刷新；仅本地详情 **dirty** 时 `flushAutosave`，否则 `reload`——**不强制回写未改表单**。

| Command | 说明 |
|---------|------|
| show/hide/toggle_floating_window | 显示/隐藏/切换整份助理；贴边再显示只恢复条 |
| show_main_window_impl | 唤出主窗：先 `collapse_panel_for_main`（钉住/Preview 退化），再 show/focus；单实例二次启动同路径 |
| toggle_main_window_impl | 托盘左键：显隐主窗口（显示走 show_main_window_impl） |
| get_active_todo_count | Todo+Doing 计数（托盘 tooltip） |
| get_companion_session | 只读会话快照，不广播 |
| companion_refresh_session | 快照并 emit（如快加后刷新计数） |
| companion_click_chrome | 球→临时面板；条/预览→钉住切换 |
| companion_minimize | Esc：贴边收条；圆球家临时板回球；面板家自由态不收条 |
| companion_collapse_to_strip | 面板 ×（历史命令名）：贴边收条；圆球家临时板回球；面板家自由态收条 |
| companion_drag_ended | 近缘吸附 / 贴边换边 / 拖离在松手处回 home；仍按下则 `{ stillDragging: true }` |
| companion_pointer_cluster | 可选悬停预览的指针与焦点；`hold` 为快加草稿保活，inside/focused 仍如实上报 |
| companion_open_view | 扩展 BodyView（当前仅 todoMini） |

**会话**：`visibility` + `placement`（free \| docked）+ `home_shape`（ball \| panel）+ `panel_mode`（closed \| preview \| pinned）。不持久化 Preview 与临时面板开着。

**几何**：工作区 `work_area`。自由态近缘吸附仍 ≤ 24px。贴边**拖条**结束用 chrome outer，阈值 `max(24, chrome.width + 8)`：Stay / Switch / Undock。贴边**拖面板**只更新 `dock_y` 并让 chrome 跟随 Y，不 undock。点球出板：w/h 用上次面板（inner），x/y 写入 `temp_body_bounds`。条视觉 16×48，HWND 可更宽；透明区 `set_ignore_cursor_events` 轮询穿透；body 按视觉 16px 让位。拖离回球/面板家：松手中心对齐。程序化 apply 约 150ms `applying`。仅 `focus_body_once`（点条/点球）时 `set_focus`；AOT 仅在设置变化时重设。`show()` 已可见则幂等。拖拽 settle 100ms。

**主窗优先 / 防闪烁**：`FloatHost::collapse_panel_for_main` 仅在 `show_main_window_impl` 调用。需退化时：cancel 悬停定时器、清 `focus_body_once`；Docked 收条或面板家收成条时 `chrome_inside=false` 并 `suppress_hover_preview`（指针离开条或约 500ms 解除；期满不自动重调度 Preview，须 leave→enter）；Ball 临时板回球、Docked 收 `Closed`、Free+Panel 内联 × 语义贴边；**单次** `apply_and_emit` 后再 show/focus 主窗。退化失败只 `warn`，仍尝试出主窗。开钉住面板路径不 hide 主窗（主窗已在则可同屏）。`schedule_preview` 尊重 suppress，避免退化后面板回弹。

圆球 HWND **强制 64×64**（`ball_pos` 只记 x/y）。两窗 `shadow: false`。chrome WebView：圆球/贴边条空闲·活跃·逾期分层材质与 hover/press；球↔条 `float-chrome` 短时 out-in（不改 HWND 时序）。

**位置记忆**（migration 007，从 `floating_window.*` 迁移；008 补齐缺键）：

| settings key | 用途 |
|--------------|------|
| companion.home_shape | 默认形态 ball / panel |
| companion.placement | free / docked |
| companion.panel_bounds | 面板**家** xywh；圆球家只更新 w/h |
| companion.ball_pos | 圆球位置 |
| companion.dock_edge / dock_y / has_docked | 贴边 |
| companion.always_on_top / visible_count / auto_show | 置顶、条数（出厂 10，设置 1–20）、启动显示 |
| companion.hover_preview | 悬停预览，默认 false |

运行时 `RuntimeState.temp_body_bounds`：圆球家临时板本次位置。`companion_collapse_to_strip`（回球时）/ 隐藏助理 / 托盘再显示回球时清空。设置球→面板且临时板开着时提交进 `panel_bounds`。

自由态 + 面板家：body `Moved`/`Resized` 写满 `panel_bounds`。自由态 + 圆球家：更新 temp + 只持久化 w/h。圆球 chrome 写回 `ball_pos`。`settings-updated` 通知刷新条数；仅 `float_default_mode` 变更且未贴边才切 home；关悬停只把 Preview→Closed。

## 3. 状态机

### 3.1 v1.0 两态（历史）

v1.1 起已启用四态，见 §3.2。

### 3.2 v1.1 四态

```mermaid
stateDiagram-v2
    [*] --> Todo: create
    Todo --> Doing: start
    Todo --> Done: complete
    Todo --> Archived: archive
    Doing --> Todo: pause
    Doing --> Done: complete
    Doing --> Archived: archive
    Done --> Todo: restore
    Done --> Archived: archive
    Archived --> Todo: restore
```

### 3.3 禁止流转（v1.1）

- Archived → Done / Doing
- Done → Doing（须 restore → Todo → start）
- 同状态 → 返回当前实体

### 3.4 命令语义

| 操作 | 命令 | 说明 |
|------|------|------|
| Done → Todo | transition_todo(id, Todo) | 清空 completed_at |
| 软删恢复 | restore_todo(id) | 清除 deleted_at，status 不变；重开软删时禁用的提醒（已过期一次性保持关闭；已过期周期跳到未来） |

合法流转 v1.2 写入 events：`todo.transitioned`，payload `{ from, to, title }`（title 为当时任务标题快照）。提醒 `reminder.triggered` / `reminder.snoozed` 同样带 `title`。`list_events` 无游标时取最新 N 条并按时间正序返回；主窗活动条再按 `createdAt` 降序展示（动作·标题·相对时间；默认收起一行摘要）。

状态机单源：`domain/status.rs` 的 `can_transition_to` / `allowed_transitions`；前端经 `get_allowed_transitions` 拉取动词按钮。

## 4. 数据设计

### 4.1 存储

- Local First，路径 `{app_data_dir}/only-todo/data.db`
- Windows: `%APPDATA%/only-todo/data.db`
- macOS: `~/Library/Application Support/only-todo/data.db`
- Linux: `~/.local/share/only-todo/data.db`
- `PRAGMA journal_mode=WAL; foreign_keys=ON;`
- 单例 `Connection` + `Mutex`（`infrastructure/database`）。`with_conn` 只持锁；`with_tx` 开启 SQL 事务。多语句与跨表写走 `with_tx`。
- 启动：`Database::new`（开库 + PRAGMA + 迁移）→ **立刻** `app.manage(AppState { db })` → 若 settings 无 `internal.tags_normalized=1` 则 `TodoRepository::backfill_normalized_tags` 并写门闩（失败则 `tracing::error!` 并阻止启动）。主窗 conf `visible: false`，`apply_startup_windows` 在 setup 末尾按 `float_auto_show` 显示助理或 show/focus main。前端 `main.ts` 挂载前短轮询 `get_settings` 直至 AppState 就绪，避免 Command 在 manage 前 invoke。

### 4.2 todos 表

```sql
CREATE TABLE todos (
    id           TEXT PRIMARY KEY,
    title        TEXT NOT NULL,
    description  TEXT NOT NULL DEFAULT '',
    status       TEXT NOT NULL DEFAULT 'Todo'
                 CHECK (status IN ('Todo','Doing','Done','Archived')),
    priority     TEXT NOT NULL DEFAULT 'Medium'
                 CHECK (priority IN ('Low','Medium','High','Urgent')),
    tags         TEXT NOT NULL DEFAULT '[]',      -- v1.2 使用
    due_date     TEXT,                            -- v1.1 新增
    created_at   TEXT NOT NULL,
    updated_at   TEXT NOT NULL,
    completed_at TEXT,
    deleted_at   TEXT
);

CREATE INDEX idx_todos_status ON todos(status) WHERE deleted_at IS NULL;
CREATE INDEX idx_todos_priority ON todos(priority) WHERE deleted_at IS NULL;
CREATE INDEX idx_todos_created_at ON todos(created_at);
```

**分期**：v1.0 migration 不含 tags/due_date 列；v1.1 加 due_date；v1.2 启用 tags JSON；v1.3+ migration 009 规范化 `tags` + `todo_tags`（JSON 仍作快照，筛选走关联表）。首次启动（或未写门闩时）幂等 backfill；成功后 settings `internal.tags_normalized=1` 跳过全表扫描；失败则阻止启动，避免「有标签却筛不到」。

### 4.2.1 tags / todo_tags（migration 009）

```sql
CREATE TABLE tags (
    name TEXT PRIMARY KEY COLLATE NOCASE,
    created_at TEXT NOT NULL
);

CREATE TABLE todo_tags (
    todo_id TEXT NOT NULL REFERENCES todos(id) ON DELETE CASCADE,
    tag_name TEXT NOT NULL COLLATE NOCASE,
    PRIMARY KEY (todo_id, tag_name),
    FOREIGN KEY (tag_name) REFERENCES tags(name) ON DELETE CASCADE
);

CREATE INDEX idx_todo_tags_tag ON todo_tags(tag_name);
```

写入任务时同步：`todos.tags` JSON 快照 + `sync_todo_tags` 维护关联表。列表按标签筛选用 `EXISTS (todo_tags … COLLATE NOCASE)`。create / update / backfill 在 `with_tx` 内完成，避免快照与关联表分叉。

### 4.3 reminders 表

```sql
CREATE TABLE reminders (
    id              TEXT PRIMARY KEY,
    todo_id         TEXT NOT NULL REFERENCES todos(id) ON DELETE CASCADE,
    remind_at       TEXT NOT NULL,
    repeat_type     TEXT NOT NULL DEFAULT 'none'
                    CHECK (repeat_type IN ('none','daily','weekly')),
    repeat_config   TEXT NOT NULL DEFAULT '{}',
    snooze_count    INTEGER NOT NULL DEFAULT 0,
    next_trigger_at TEXT NOT NULL,
    enabled         INTEGER NOT NULL DEFAULT 1,
    created_at      TEXT NOT NULL,
    updated_at      TEXT NOT NULL
);

CREATE INDEX idx_reminders_next_trigger ON reminders(next_trigger_at) WHERE enabled = 1;
CREATE INDEX idx_reminders_todo_id ON reminders(todo_id);
```

repeat_config：

```json
// daily: {}
// weekly: { "weekdays": [1, 3, 5] }  // 0=周日
```

> 统一使用 `none` 表示一次性提醒，不使用 `once`。

### 4.4 settings 表

```sql
CREATE TABLE settings ( key TEXT PRIMARY KEY, value TEXT NOT NULL );
```

预置 key：companion.*、main_window.bounds、autostart.enabled、list.default_sort、`list.default_view`（默认 `all`；合法值 all/done/archived/trash，非法与 `tag`/`today`/`doing`/`overdue` 回落 all）、notification.enabled、`ui.theme`（默认 system）、`ui.locale`（默认 zh-CN）

`update_settings`：先写 SQLite；仅当 `autostart.enabled` **相对当前值变化** 时再调 `tauri-plugin-autostart`。OS 同步失败（开发态路径、Windows 无启动项时报 os error 2 等）只打日志，**不回滚已保存偏好**、不阻断其它设置项。`ui.theme` 变更走宿主 `sync_from_settings` → 全窗 `set_theme`，不经前端涂 DOM。`ui.locale` 变更经 `settings-updated` 同步三窗 vue-i18n，并更新托盘文案。`list.default_view` 仅影响下次主窗冷启动落点，不因 `settings-updated` 切换当前页；写入 `tag`/`today`/`doing`/`overdue` 时回落为 `all` 再落库。

### 4.5 events 表（v1.2）

```sql
CREATE TABLE events (
    id          TEXT PRIMARY KEY,
    entity_type TEXT NOT NULL CHECK (entity_type IN ('todo','reminder')),
    entity_id   TEXT NOT NULL,
    event_type  TEXT NOT NULL,
    payload     TEXT NOT NULL DEFAULT '{}',
    created_at  TEXT NOT NULL
);
```

payload 为 JSON 文本。状态变更 `{ from, to, title }`；`reminder.triggered` `{ repeatType, title }`；`reminder.snoozed` `{ minutes, title }`。`title` 为写入时的任务标题快照；旧行可能没有。

### 4.6 schema_version 与迁移

```sql
CREATE TABLE schema_version ( version INTEGER PRIMARY KEY, applied_at TEXT NOT NULL );
```

清单在 `src-tauri/src/infrastructure/database/migrations.rs`，SQL 在 `src-tauri/migrations/`。启动检查 `MAX(version)` → 按序执行未应用文件 → **与 `schema_version` 写入同一事务**，失败回滚并阻止启动。

### 4.7 完整性

- 软删任务不级联删 reminders，但 `enabled=0`；`TodoService::delete` / `restore` 在同一 `with_tx` 内完成任务行与提醒开关，避免只改了一半。Scheduler 对 deleted todo 仅 advance 到未来、不通知
- `restore_todo` 调用 `ReminderRepository::reenable_after_restore`：未来触发时间的提醒重新 `enabled=1`；已过期周期推进到下一槽；已过期一次性保持关闭（避免恢复瞬间通知洪水）
- `SettingsRepository::update` 一次事务写完全部变更 key 并在同一连接读回 DTO；`get` 一次持锁读齐展示字段
- 写路径成功后 emit `todos-changed`（见 `broadcast::emit_todos_changed`），主窗/助理监听刷新列表与计数，并更新托盘 tooltip；主窗无 dirty 时不回写表单
- 通知 / 助理详情进主窗 `navigate-to-todo`：主窗按需切到 trash 或 all，再选中，保证列表露出该行
- 空态 CTA「添加任务」打开新建弹窗（标签页会预填当前 tag）
- 提醒配额仅计 `enabled=1`；列表 due 筛选上界为半开区间 `< before`，与角标 count 一致

## 7. Scheduler 与后台任务

### 7.1 运行时

Tokio Async Runtime，结构：`Scheduler → Worker → Service`

### 7.2 tick 策略

| 参数 | 值 |
|------|-----|
| tick 间隔 | 30 秒 |
| 扫描条件 | `enabled=1 AND next_trigger_at <= now()` |
| missed 策略 | 启动首 tick **仅** catch-up：补发 24h 内未触发（每条至多一次通知）；更早的只 `advance` 到未来；下一 tick 起常规扫描 |
| advance | 一次性 `enabled=0`；daily/weekly 跳到严格大于 `now` 的下一槽（避免 downtime 刷屏） |
| 通知关闭 | 仍 `advance` due 行，仅跳过 `NotificationService::send` |
| 通知失败 | 进程内指数退避（60s 起，上限 30min）；连续失败 5 次后 `advance` 并打 warn，避免每 tick 刷屏 |

### 7.3 触发流程

```
tick → 查询到期 reminders
     → deleted todo / 通知关闭 / catch-up 超 24h：仅 advance（跳到未来）
     → 否则 NotificationService.send
         → 成功：ReminderService.advance
         → 失败：退避后重试；超限则 advance
     → none: enabled=false | daily/weekly: next_trigger_at > now
     → v1.2: 写 events reminder.triggered（仅实际通知路径）
```

### 7.4 约束

- 不阻塞 UI 主线程
- 避免 busy-loop；使用 tokio::time::interval

### 7.5 内部接口（非 Tauri Command）

- `Scheduler::tick()`
- `NotificationService::send(app, NotificationPayload)`
- `ReminderService::advance(reminder)`

### 7.4 应用内更新（Tauri updater）

要点：

- **插件**：`tauri-plugin-updater`（`check` / `downloadAndInstall`）+ `tauri-plugin-process`（`relaunch`）；`single_instance` 须最先注册，其后为 process/updater
- **配置**：`tauri.conf.json` → `bundle.createUpdaterArtifacts: true`；`plugins.updater.pubkey` + **双 endpoint**（优先公开 GitHub 代理上的 `latest-cn.json`，失败回落官方 `latest.json`）；Windows `installMode: passive`
- **权限**：`src-tauri/capabilities/desktop.json` 仅 `main` 窗 → `updater:default`、`process:default`
- **前端**：`useAppUpdater` composable（`flowInFlight` 互斥 + `checking` 状态）；`AppConfirm` 一次确认 → `UpdateProgressModal`（含 indeterminate 进度与 a11y）→ `relaunch`
- **安装前**：`flushAutosave()`；updater 安装时插件内部调用 `cleanup_before_exit`（SQLite WAL 已落盘）
- **国内加速**：发版后 `scripts/rewrite-updater-manifest.mjs` 将 `platforms.*.url` 加上 `GH_PROXY_PREFIX`（默认 `https://ghfast.top/`）生成 `latest-cn.json` 并上传同一 Release；`signature` 不改（校验文件内容）。CSP `connect-src` 含代理主机。镜像失效时改仓库 Variable `GH_PROXY_PREFIX` 与 conf endpoints/CSP。
- **CD**：`release.yml` 将 `TAURI_SIGNING_PRIVATE_KEY` 注入环境变量（不内联进脚本，避免多行私钥在 Windows `pwsh` 下解析失败）；构建前校验 Secret 非空，并对临时文件执行 `tauri signer sign` dry-run（校验私钥/密码可用，失败不进入完整构建）；tag 推送时校验 `refs/tags/v*` 与 `tauri.conf.json` version 一致；`releaseDraft: false`（Draft 对外不可见，updater 拉不到）。私钥须与 `plugins.updater.pubkey` 同一次 `signer generate` 成对。
- **跳过版本**：`localStorage` key `only-todo:skipped-update-version`
