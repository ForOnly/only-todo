### 1.7 悬浮窗（v1.1）

[`tauri.conf.json`](../src-tauri/tauri.conf.json) 定义 `float` 窗口（frameless、transparent、alwaysOnTop）。单窗口 + 前端三态 + Rust 动态 `set_size`/`set_position`。

| Command | 说明 |
|---------|------|
| show_floating_window | 显示/聚焦；`docked` 保持挂边，否则按 `default_mode` 恢复 |
| hide_floating_window | 隐藏 |
| toggle_floating_window | 托盘左键切换 |
| get_active_todo_count | Todo+Doing 计数（托盘 tooltip） |
| get_float_window_state | 运行形态、主形态、挂边方向、计数 |
| set_float_display_mode | 切换 ball / panel / docked（先写 mode 再改尺寸；几何失败回滚 mode） |
| dock_float_window | 手动或指定边缘挂边（HWND 48×64，视觉 8px） |
| undock_float_window | 回到 `default_mode` 主形态 |
| try_dock_on_edge | 拖拽结束后边缘检测（阈值 24px，仅左右）；拖离回到主形态 |
| peek_docked_float | 挂边悬停：临时展开 panel 尺寸（不改 mode） |
| unpeek_docked_float | 挂边移开：收回 48×64 竖线 |
| is_primary_mouse_down | OS 级左键是否按下（拖拽 settle 用） |

**主形态**：`floating_window.default_mode`（ball \| panel）为用户设置；`display_mode` 为运行时 HWND。ball 主形态下展开 panel 不改 default_mode；托盘再显示时临时 panel 不保留。保存设置时若未挂边则立即切到新主形态；已挂边不 unpeek。

**挂边算法**：`current_monitor().work_area` 取可用区域；距左/右缘 ≤ 24px 进入 docked。挂边 HWND **48×64**（与圆球同高）全部落在工作区内（右：`x=work_x+work_w-48`，`y` 取当前窗并 clamp）；前端在外缘画 **8px** 蓝条。`peek_docked_float(client_y)` 用 `inner_position/scale + clientY` 得逻辑屏幕 Y 后纵向对齐；挂边方向写入 `floating_window.dock_edge`。程序化改尺寸期间 `FloatGeometryLock`（Atomic 世代 + 短延迟解锁）抑制 `Moved`/`Resized` 写回；`apply_float_bounds` 关闭系统阴影并 `show`。拖拽吸附：`onMoved` 静止约 180ms 后查 `GetAsyncKeyState(VK_LBUTTON)`，仍按下只重臂，抬起再 `tryDock`；`pointerup` 快路径；自上次 Moved 起 3s 安全超时（键仍按下则重臂）。拖离 / 取消挂边回到 `default_mode`。托盘左键：窗口可见但过小/飞出工作区时视为丢失，走 show+修复而非 hide。

圆球 HWND **强制 64×64**（`ball_bounds` 只有效记忆 x/y）。float 窗 `shadow: false`。

**位置记忆**（migration 006）：

| settings key | 用途 |
|--------------|------|
| floating_window.display_mode | 当前形态 |
| floating_window.default_mode | 设置页默认形态（保存时同步到 display_mode） |
| floating_window.panel_bounds | panel 位置尺寸 |
| floating_window.ball_bounds | 圆球位置 |
| floating_window.dock_edge | 挂边方向（left/right） |

`Moved`/`Resized` 在非 lock、非 docked 时写回 ball/panel bounds；`settings-updated` 事件通知 float 刷新可见条数。

## 4. 数据设计

### 4.1 存储

- Local First，路径 `{app_data_dir}/only-todo/data.db`
- Windows: `%APPDATA%/only-todo/data.db`
- macOS: `~/Library/Application Support/only-todo/data.db`
- Linux: `~/.local/share/only-todo/data.db`
- `PRAGMA journal_mode=WAL; foreign_keys=ON;`

### 4.2 todos 表

```sql
CREATE TABLE todos (
    id           TEXT PRIMARY KEY,
    title        TEXT NOT NULL,
    description  TEXT NOT NULL DEFAULT '',
    status       TEXT NOT NULL DEFAULT 'Todo'
                 CHECK (status IN ('Todo','Doing','Done','Archived')),
    priority     TEXT NOT NULL DEFAULT 'Medium'
                 CHECK (priority IN ('Low','Medium','High','Urgent')),
    tags         TEXT NOT NULL DEFAULT '[]',      -- v1.2 使用
    due_date     TEXT,                            -- v1.1 新增
    created_at   TEXT NOT NULL,
    updated_at   TEXT NOT NULL,
    completed_at TEXT,
    deleted_at   TEXT
);

CREATE INDEX idx_todos_status ON todos(status) WHERE deleted_at IS NULL;
CREATE INDEX idx_todos_priority ON todos(priority) WHERE deleted_at IS NULL;
CREATE INDEX idx_todos_created_at ON todos(created_at);
```

**分期**：v1.0 migration 不含 tags/due_date 列；v1.1 加 due_date；v1.2 启用 tags。

### 4.3 reminders 表

```sql
CREATE TABLE reminders (
    id              TEXT PRIMARY KEY,
    todo_id         TEXT NOT NULL REFERENCES todos(id) ON DELETE CASCADE,
    remind_at       TEXT NOT NULL,
    repeat_type     TEXT NOT NULL DEFAULT 'none'
                    CHECK (repeat_type IN ('none','daily','weekly')),
    repeat_config   TEXT NOT NULL DEFAULT '{}',
    snooze_count    INTEGER NOT NULL DEFAULT 0,
    next_trigger_at TEXT NOT NULL,
    enabled         INTEGER NOT NULL DEFAULT 1,
    created_at      TEXT NOT NULL,
    updated_at      TEXT NOT NULL
);

CREATE INDEX idx_reminders_next_trigger ON reminders(next_trigger_at) WHERE enabled = 1;
CREATE INDEX idx_reminders_todo_id ON reminders(todo_id);
```

repeat_config：

```json
// daily: {}
// weekly: { "weekdays": [1, 3, 5] }  // 0=周日
```

> 统一使用 `none` 表示一次性提醒，不使用 `once`。

### 4.4 settings 表

```sql
CREATE TABLE settings ( key TEXT PRIMARY KEY, value TEXT NOT NULL );
```

预置 key：floating_window.*、main_window.bounds、autostart.enabled、list.default_sort、notification.enabled

### 4.5 events 表（v1.2）

```sql
CREATE TABLE events (
    id          TEXT PRIMARY KEY,
    entity_type TEXT NOT NULL CHECK (entity_type IN ('todo','reminder')),
    entity_id   TEXT NOT NULL,
    event_type  TEXT NOT NULL,
    payload     TEXT NOT NULL DEFAULT '{}',
    created_at  TEXT NOT NULL
);
```

### 4.6 schema_version

```sql
CREATE TABLE schema_version ( version INTEGER PRIMARY KEY, applied_at TEXT NOT NULL );
```

迁移策略：启动检查 version → 按序执行 `{version}_{description}.sql` → **与 `schema_version` 写入同一事务**，失败回滚并阻止启动。

### 4.7 完整性

- 软删任务不级联删 reminders，但 `enabled=0`；Scheduler 对 deleted todo 仅 advance 到未来、不通知
- 提醒配额仅计 `enabled=1`；列表 due 筛选上界为半开区间 `< before`，与角标 count 一致

## 7. Scheduler 与后台任务

### 7.1 运行时

Tokio Async Runtime，结构：`Scheduler → Worker → Service`

### 7.2 tick 策略

| 参数 | 值 |
|------|-----|
| tick 间隔 | 30 秒 |
| 扫描条件 | `enabled=1 AND next_trigger_at <= now()` |
| missed 策略 | 启动首 tick **仅** catch-up：补发 24h 内未触发（每条至多一次通知）；更早的只 `advance` 到未来；下一 tick 起常规扫描 |
| advance | 一次性 `enabled=0`；daily/weekly 跳到严格大于 `now` 的下一槽（避免 downtime 刷屏） |
| 通知关闭 | 仍 `advance` due 行，仅跳过 `NotificationService::send` |

### 7.3 触发流程

```
tick → 查询到期 reminders
     → deleted todo / 通知关闭 / catch-up 超 24h：仅 advance（跳到未来）
     → 否则 NotificationService.send → ReminderService.advance
     → none: enabled=false | daily/weekly: next_trigger_at > now
     → v1.2: 写 events reminder.triggered（仅实际通知路径）
```

### 7.4 约束

- 不阻塞 UI 主线程
- 避免 busy-loop；使用 tokio::time::interval

### 7.5 内部接口（非 Tauri Command）

- `Scheduler::tick()`
- `NotificationService::send(app, NotificationPayload)`
- `ReminderService::advance(reminder)`

### 7.6 通知实现

```mermaid
sequenceDiagram
    participant Sched as Scheduler
    participant Notif as NotificationService
    participant Plugin as tauri_plugin_notification
    participant Pending as PendingNavigation
    participant FE as Frontend

    Sched->>Notif: send(payload)
    Notif->>Plugin: title/body.show
    Notif->>Pending: 写入 todo_id
    Note over Pending,FE: 窗口 Focus 时 emit navigate-to-todo
```

要点：

- **展示通道**：`tauri-plugin-notification`（唯一路径，不使用 notify-rust）
- **Windows 启动**：`SetCurrentProcessExplicitAppUserModelID` 设置 AUMID
- **点击跳转**：`PendingNavigation` + `WindowEvent::Focused` → 前端监听 `navigate-to-todo`
- **日志**：`app.log` 记录 sent / failed
